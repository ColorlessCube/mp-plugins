# mp-plugins

MoviePilot 自用插件库，用于在插件市场中展示和安装。

## 仓库结构

- **package.json**：插件市场列表与元数据（必填，且每个插件需带 `"v2": true` 才会显示）
- **plugins/**：插件代码目录，子目录名为插件 ID 的小写形式（如 `traktratingssync`）
- **icons/**：插件图标（可选）

## 当前插件

| 插件 ID | 说明 |
|--------|------|
| TraktRatingsSync | 从 Trakt 读取用户电影评分，匹配豆瓣条目并同步为「看过」及评分 |

## 在 MoviePilot 中使用

1. 设置 → 插件 → 插件市场，添加仓库地址：`https://github.com/ColorlessCube/mp-plugins`
2. 刷新后可在市场中找到并安装「Trakt 评分同步豆瓣」
3. 安装后配置 Trakt 用户名、Client ID 及有效的豆瓣 Cookie。

## 配置与授权（3.17.0 起）

配置页保留基础设置与豆瓣 Cookie，其余平台、通知及高级设置按原生折叠面板分组。
Cookie、API Key 和 Bark 地址按密码输入显示。读取数量不是实际写入额度；
“Trakt 最近评分读取上限”只控制 Trakt 评分候选范围，所有平台共用豆瓣写入额度。

Trakt 仅支持 PKCE，已删除 Client Secret、设备码轮询、手动回跳、授权方式选择和一次性配置开关。
旧配置升级时保留并迁移已有 Access Token 到插件私有数据，保留 Refresh Token 和同步历史；
配置中不再保存令牌、授权链接或授权结果消息。废弃网易云开放平台实现已移除，仅保留 Cookie 模式。
Trakt 用户名仍用于公开评分接口，不能省略。

1. 在 Trakt 开发者后台登记 `https://你的MoviePilot域名/api/v1/plugin/TraktRatingsSync/oauth/callback`。独立端口需包含端口；不支持 localhost、私有IP、旧OOB或没有接收接口的路径。
2. 在插件配置中填写用户名、Client ID 和完全相同的回跳地址，先保存。修改配置不会自动发起授权或同步。
3. 在同域名浏览器登录 MoviePilot 管理员，展开 Trakt，点击“生成授权链接”或“重新授权”。按钮使用已保存的应用配置；生成后本页立即显示“打开 Trakt 授权页面”，无需关闭重开。
4. 在同一浏览器完成授权，回跳接口会校验管理员资源 Cookie 与一次性 state，交换并私下保存令牌。链接有效期10分钟，不需要复制回跳地址，也不在URL中携带MoviePilot API key。
5. 授权后返回配置页确认已保存授权；令牌自动续期，授权本身不启动同步。

`POST /api/v1/plugin/TraktRatingsSync/oauth/start` 和
`POST /api/v1/plugin/TraktRatingsSync/douban/resume` 使用管理员资源 Cookie 鉴权，
返回标准中文 JSON 响应；授权开始接口只返回短期授权链接，不返回令牌或启动同步。
恢复按钮仅在人工验证暂停时显示；先完成浏览器验证再点击，不会跳过429冷却。
生成新请求保留现有令牌，只有新授权成功时替换；更换Client ID则只重置Trakt授权，保留所有平台记录。403时仍须确认Trakt应用存在并具有访问权限。

## 剧集完成判断（3.18.0 起）

- 剧集“在看”和“看过”不要求评分。播放进度与最近观看历史用于发现剧集，仅处理近期观看的季和已跟踪的季，避免批量回填全部历史季度；已经跟踪的在看季即使离开历史窗口也继续核对。旧在看缓存补全媒体信息后，核对原自动匹配的第一季，并保留原记录。
- 使用 Trakt `/shows/{id}/progress/watched?hidden=true&specials=false` 的逐集观看记录，以及 `/shows/{id}/seasons?extended=full` 的季度总集数。只有总集数大于0、已播集数等于总集数、逐集全部看过且没有缺集，才同步该季“看过”；追平正在更新的剧仍为“在看”。特别篇不参与完成判断，未知总集数或接口失败不能推断完成。
- 按季调用 MoviePilot 媒体链匹配豆瓣条目，不将整剧映射复用于第二季等后续季。手动映射示例 `show:123:s2=12345678` 或 `tmdb:456:s2=12345678`；旧通用映射只兼容第1季。不同季落到同一条目时跳过并记录冲突。
- 已知“看过”状态不会被单集播放降回“在看”，已同步的评分会保留；未评分的完成季只同步状态。写入仍共享每轮额度和间隔，延期进入原有待处理队列，不提前标记成功。
- 详情表格增加“已看 / 全季集数”。Trakt 元数据可能延迟或调整，判断以当轮能够核对的完整季度信息为准；重看起点之前的集数不会被用来新判定完成。

参考：[Trakt 观看进度说明](https://trakt.docs.apiary.io/reference/shows/watched-progress/get-show-watched-progress)、[Trakt 季度说明](https://trakt.docs.apiary.io/reference/seasons/summary/get-all-seasons-for-a-show)。

## 同步详情与通知（3.17.0 起）

- 概览显示最近开始/完成时间、下一次定时执行时间、本轮真实写入、未变化跳过、实际提交失败与待处理数量；部分平台鉴权失败会显示“部分完成”。
- 待处理列表显示目标名称、来源、延期或提交错误原因及豆瓣链接。来源窗口之外的待处理目标仍由队列继续处理；旧队列未保存名称时显示豆瓣条目ID。
- 平台记录按折叠面板展示，每个平台默认展示最近20条并注明总数，另提供包含队列补交的最近成功写入记录。微信读书和小宇宙明确分开来源进度与豆瓣同步结果；小宇宙按播客合并多条单集。
- 页面以持久化实际提交缓存判断成功，独立队列补交成功后也能显示真实状态。尚未提交或匹配的来源记录不会被称为同步成功。
- 通知选择“新增汇总及异常”“仅异常和恢复”或关闭；全部状态未变化时不推送常规摘要，有新增时每轮只发一条数量摘要。
- 通道为MoviePilot已配置通道或Bark二选一，避免重复推送。升级时已有Bark地址继续使用Bark，其余默认MoviePilot；MoviePilot返回只表示交给宿主通道，不能证明手机已收到。
- 相同凭据和异常成功投递后冷却6小时。投递失败不消耗成功冷却，至少间隔5分钟，下次来源检查时可重试；不在后台持续循环推送。
- 有效数据确认来源恢复后只推送一次恢复消息。恢复推送失败会保留重试，但页面已清除故障。通知默认不包含具体书影音标题或接口诊断正文。

## 豆瓣请求节制（3.16.0 起）

- 同一剧集的播放进度与观看历史合并，每轮只提交一次；已成功标记为在看的剧集，状态及隐私设置未变化时只更新本地进度。
- 所有平台共用每轮写入上限（默认 10 次，失败请求也占额度）和等待间隔（默认每次写入后等待 10–20 秒）。这是保守起始配置，不是豆瓣公布的安全阈值。
- 超过额度或提交未确认成功时，目标状态保存在插件私有待同步队列；不保存 Cookie、ck 或原始响应。同一目标的最新状态覆盖旧目标，旧待处理条目优先。队列可处理已经离开来源最近记录窗口的条目。
- 提交超时或网关异常不立即重试，每个目标每轮最多尝试一次；连续三次网络/网关失败暂停一小时。成功响应必须明确确认写入，避免验证码页或错误 JSON 被记录为成功。
- 识别验证码内容、安全验证跳转或写入被拒绝后，停止本轮后续豆瓣请求。暂停状态跨重载保存；在正常浏览器完成验证后，更新 Cookie，或点击“已完成验证，恢复同步”按钮。普通条目 404 单独延期，不直接认定 Cookie 失效。
- 429 冷却遵守 `Retry-After`，没有有效值时等待一小时；恢复按钮不跳过服务端冷却。已有搜索限流仍保留。
- 3.16.1 起，详情页与通知区分人工验证和自动冷却；网络/限流冷却到期后在下一次定时任务继续，无需更新 Cookie。
- 定时与手动触发共用运行锁，避免重复任务同时写入。详情页展示待处理数量与暂停原因，日志单独汇总实际新增、缓存跳过、失败及待处理数量。

验证暂停时尚未匹配的来源条目留待后续重新拉取；持久化队列保存已经确定豆瓣目标的请求。需要补齐较早电影记录时，请调整“Trakt 最近评分读取上限”，它仍控制 Trakt 评分候选范围，并非全平台写入上限。
